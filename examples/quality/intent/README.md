# 初衷对齐回归材料

本目录包含六个虚构案例，每例十四条消息，覆盖方案、简短采纳、用户质疑或约束、代码实现报告和验收。
三组配对各只改变一条 AI 验收回应，分别检查恢复验证、跨部门泛化和离线演示的持久化验证。
同组两例处于同一 split。`holdout` 仅是公开冻结的分组，不是秘密或当前作者未见的材料。

`comparators/before.md` 是修改前完整 Skill、分析方法和报告表达规范的快照；`after.md`
使用相同范围的修改后快照。`provenance.json` 保存哈希。历史轮次材料和产出没有修改。
这里比较核心分析内容，不比较客户端获取会话或安装流程，也不代表独立模型能力。

## 冻结的重点评审问题

沿用现有七维评分与严重错误规则，额外在评语中检查以下问题，不另建总分：

1. 是否发现尚未补足、且与记录中的目标直接相关的重要缺口？
2. 是否连接 AI 提案、用户回应、依据和后续结果，保留纠正与范围限制？
3. 具体追问、验证或比较能补充什么决策依据？是否只是重复已完成的检查？
4. 是否将未讨论误写为没思考，或将 AI 断言、执行问题归给用户？
5. 只变更验收证据时，意见是否随之收窄或撤回，其余判断是否保持稳定？

缺口例预设方向为 required，已补足例为 unnecessary；后者不禁止有依据且有增量价值的建议。
这些是待检验的评审政策，不是语义真理。遗漏、无依据建议和严重误判分别报告。

## 复跑

```bash
python3 scripts/compare_quality.py prepare --cases examples/quality/intent/cases.json --comparators examples/quality/intent/comparators --output runs/quality-intent-new --repeats 3 --opaque
```

该命令仅准备 36 份任务，不调用模型。生成者只读取所分配的任务；不能读取案例答案、配对或
方向政策。后续按[质量评测流程](../../../docs/development/quality-benchmark.zh-CN.md)生成、匿名评审和汇总。
已参与本次修改、看过判据的上下文不能作为独立盲评者。工具就绪与任务准备不能计作比较完成。

`analysis-example.json` 是针对恢复缺口例人工编写的回放示例，展示现有 schema 如何表达纯授权、
AI 归因和具体建议。它不是模型原始输出，也不能进入匿名评测或证明修改后质量更高。
