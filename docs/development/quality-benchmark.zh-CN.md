# 产出质量对比评测

本评测回答的是“在相同原始材料上，哪种分析方式更忠实、公平、有用”，不评价人的能力，
不以报告篇幅、问题数量或引用校验成功替代质量。它与 CLI 的结构测试分开。

## 测试集

[cases.json](../../examples/quality/cases.json) 包含 24 个人工构造案例，全部为中文虚构对话，
无真实账号、用户记录或项目秘密。每个案例有稳定消息 ID；材料中的助手或用户结果报告也只是报告。

| family | 划分 | 主要检查 | 案例数 |
| --- | --- | --- | --- |
| framing | dev | 目标与验收标准是否匹配，是否捏造隐含目标 | 3 |
| tradeoff | dev | 预算、时间、可逆性下的方案取舍 | 3 |
| temporal | dev | 决策当时信息、事后结果、文档版本时点 | 3 |
| provenance | dev | 授权、明确选择、复制方案与原创归属 | 3 |
| execution | holdout | 人的边界、AI 执行偏差、计划与结果 | 3 |
| causality | holdout | 混杂、限定对照、碰巧成功 | 3 |
| correction | holdout | 接受或拒绝纠正、晚出现的反证 | 3 |
| transfer | holdout | 认可与后续证据、产物质量与人的判断 | 3 |

每个 family 有一组最小差异配对，共八组。配对尽量保持前文相同，只改变决定性证据：
验收标准、预算、结果、选择的明确程度、是否越界、是否控制混杂、是否纠正、是否有后续行为证据。
评审既检查该改变是否影响应变的结论，也检查不该改变的判断是否保持稳定。
其中六组仅改一条消息；`temporal_outcome` 和 `causality_control` 同时改变结果/证据消息与
用户的后续表态，属于两条关联消息变化。后两组不能用于隔离某一条证据的独立影响。

`dev/holdout` 按整个 family 分组，同一对不会跨两边。这里的 holdout 是公开冻结的评测分组，
不是秘密测试，也不保证模型训练中未见过相似问题；看过后不得再称为未见材料。
若后续使用这些 holdout 结论调整 Skill，新一轮评测需要增加全新且按 family 隔离的材料。

生成者只收到原始 `messages` 和所属比较臂提示，不接收 family、pair_id、split 或
`expected`。首轮任务文件名仍含语义化案例 ID，可能提示主题；这属于已知线索泄露，
不得把首轮生成称为完全无案例线索的盲测。`expected.must_find` 和 `expected.must_avoid` 是评审检查点，不是模型输出的标准措辞，
也不是要求每个报告照抄所有项目；不能用字符串命中计算语义质量。

## 比较臂与可比性

第一轮比较使用当前 SteerTrace、通用复盘提示及
[AMDResearch/dh_comms 的 session-review](https://github.com/AMDResearch/dh_comms/blob/ad8f2317cc7301614b7cdbcf744f00cb0e4a8b5a/.agents/skills/session-review/SKILL.md)
在“仅提供对话”条件下的适配提示。外部来源的提交号、许可证与内容摘要或哈希应保存在
`examples/quality/sources/`，具体比较提示保存在 `examples/quality/comparators/`。
外部适配保留其复盘侧重点，但不模拟其未执行的工具、会话抓取或持续改进系统。
**适配提示的结果只代表这个适配条件，不能宣称原项目或完整 Skill 的质量排名。**

同一轮应使用相同模型、推理设置、单案例任务、生成预算、证据和输出格式，每个比较臂使用
隔离的生成上下文。记录实际模型与设置；宿主未暴露的参数标为未知，不臆造温度或精确 token 限额。
统一简洁 JSON 便于交换结果，不强迫所有比较臂执行 SteerTrace 的推理步骤或 CLI 报告管线。
比较对象是分析内容，不能因某臂没有生成相同 HTML 就扣质量分。

同一模型的不同子代理提供上下文隔离，不代表不同模型或真正统计独立。一次运行只形成探索性证据；
完整稳定性结论需要重复运行、换序评审和人工抽查。对比中不安装外部技能到用户全局目录。

## 七个质量维度

评分为 0–4；不适用为 `null`，不能把不适用或缺失产出当零分。

| 维度 | 字段 | 评审重点 |
| --- | --- | --- |
| 证据忠实 | evidence_fidelity | 引文和事实是否准确，是否清楚区分自报、推断与独立验证 |
| 当时判断 | decision_time | 是否按当时可得信息评价，避免事后偏见 |
| 方案取舍 | tradeoffs | 是否结合记录中的目标、候选方案、代价与约束 |
| 错误归因 | causal_attribution | 是否比较相关解释，保留混杂、反证与未知 |
| 强化价值 | direction_value | 方向是否回应关键缺口或有效做法，是否能迁移到类似判断 |
| 可检验性 | testability | 是否提出可观察变化和可能削弱方向的证据，避免把认可当效果 |
| 明确性 | clarity | 结论是否具体易懂，重要限定可见，避免空话与训诫 |

通用分档：0 为与材料明显相反或严重捏造；1 为主要问题处理错误或大量遗漏；2 为基本正确但
关键关系不完整；3 为正确且具体，存在次要可改进处；4 为在此材料范围内充分准确、具体且有边界。
不以固定字数、术语数量、引用数量、建议数量或是否“看起来像 SteerTrace”给高分。
无错误的案例允许空批评；没有值得新增的方向允许空列表。方向缺失是否扣分取决于材料是否足以
支撑有价值的方向；本来不适用则用 `null` 并说明理由。不得为了满足评分表制造问题。

## 严重误判单列

以下出现时，除相关维度反映外，单独记录具体句子、消息依据和原因：

- 捏造事实、结果、用户动机或长期能力；把 AI 提案全部归为人的原创判断。
- 把 AI 执行错误归为用户未限定范围；把后见信息当成当时已知。
- 在有混杂或只有自报时确定根因或声称独立验证。
- 忽略后续关键纠正，保留已被反证的指责。
- 把认可、采纳、计划或一次成功写成思维改善已获证实。

严重误判不得藏进平均分。汇总需同时呈现每维分布/均值、可用评分数、严重错误数、完成覆盖率和
同案例两臂的胜/负/平。缺失产出或未评分单列，不能通过排除困难案例制造优胜结果。

## 执行与留痕

`scripts/compare_quality.py` 负责准备任务、汇集实际产出、匿名化评审与评分汇总，具体参数见
`python3 scripts/compare_quality.py --help`。它不调用外部模型，也不自动判断语义正确性。

1. 冻结 cases、各臂提示与来源，并记录哈希；准备生成任务。
2. 独立生成各臂各案例的原始输出，保存实际模型、上下文设置和覆盖情况，不手改输出以匹配判据。
3. 随机化匿名输出标签和顺序，生成评审包；生成者看不到 expected，评审者看不到比较臂映射。
4. 独立评审七维质量与严重错误，记录支撑评分的原输出句子和原始消息依据，允许平局与 null。
5. 检查评分数据完整性后解盲、汇总；抽查高分、严重错误及最小差异配对。
6. 报告只在实际覆盖的案例和条件内下结论。单轮小样本无显著性宣称，不证明长期思维强化效果。

匿名化会隐藏标签，不能消除文风、格式或术语泄露的身份线索；评审模型可能偏爱自身风格。
因此盲评称为“隐去比较臂标识的评审”，不称为不可识别的双盲实验。若同一上下文已经见过原始臂身份，
其评分只能算非盲复核，不得混称独立盲评。示例评分或人工预写分析只能用于工具演示，不能作真实模型优胜证据。

## 复跑命令与评分格式

准备新的空目录（命令不调用模型）：

```bash
python3 scripts/compare_quality.py prepare --output runs/quality-new
```

将 `generation/<比较臂>/<案例>.md` 交给隔离的生成者，原始 JSON 保存到
`outputs/<比较臂>/<案例>.json`。保持实际输出，结构失败也应留痕，不得参照答案润色。
默认对全部案例执行；`prepare --case-ids id1,id2` 可显式指定子集，报告须说明范围。

```bash
python3 scripts/compare_quality.py blind --run runs/quality-new --output runs/quality-new/blind --seed 42
```

评审者只读 `blind/submissions.json`、`blind/rubric.json` 和评分模板，不能读取
`manifest.json`、原始 outputs 路径或 `blind/private/mapping.json`。实际采用的评分细则若有补充，
需在评分前冻结并记录。模板每项含七维 `scores`、`not_applicable`、`severe_errors` 与 `rationale`。
`rationale` 的每项用 `quote` 精确引用输出中的一句话，用 `reason` 解释相关维度为何得到该分；
引用通过仍不证明评分公平。每个不适用维度在 `not_applicable` 中说明原因。

```bash
python3 scripts/compare_quality.py summarize --run runs/quality-new --blind runs/quality-new/blind --ratings runs/quality-new/ratings.json --output runs/quality-new/summary.json
```

汇总按同案例双方共同适用的维度等权比较，展示胜、负、平与可比较维度分母；
`matched_dimensions` 另给出所有臂共同适用案例的均值，避免跨不同样本集合直接比较；该胜负是七维评分的
派生统计，不是另一次直接偏好投票。工具不自动宣称总冠军。严重错误独立列出，dev/holdout 分开汇总。
未完成输出默认拒绝盲评；确需部分评测时显式使用 `blind --allow-missing`，报告覆盖率与缺失清单。
配对敏感性可另交给匿名评审，保存 `pair_id`、同方法的两条 `submission_ids`、
`assessment`（responsive / insensitive / overreacted / uncertain）、`reason` 和双方输出的
`quotes`（submission_id 与 quote）。汇总时添加 `--pair-ratings 文件路径`；工具核对配对身份、
原话和覆盖情况，不自动判断语义是否响应。主评审分数与配对敏感性单独呈现。

结果在本地 `runs/` 下保存，不将真实记录或生成运行目录提交到 Git。
